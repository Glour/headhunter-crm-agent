# HeadHunter CRM Agent

CRM для поиска работы: сбор вакансий, оценка соответствия профилю, подготовка черновиков откликов и учёт обратной связи. Проект объединяет Python/FastAPI, SQLite и React/TypeScript; интеграции с HH и Telegram вынесены в отдельные компоненты.

## Возможности

- Детерминированный скоринг с объяснением совпадений и ограничений.
- Хранение вакансий, откликов, статусов и обратной связи в SQLite.
- Подготовка писем на основе профиля и данных вакансии с проверкой результата.
- Дашборд вакансий, черновиков, этапов отклика и обратной связи.
- Интеграции для поиска вакансий, работы с браузером и Telegram-уведомлений. Отправка во внешние сервисы настраивается отдельно.

## Посмотреть демо

Для демонстрации не нужны аккаунт HH, браузерный профиль или токены. Используются вымышленные вакансии, настоящий модуль оценки и временная SQLite-база. В демо нет маршрутов отправки, поиска на HH или подключения к Telegram.

Требования: Python 3.11 или новее. Из корня проекта:

```bash
python3 -m pip install uv==0.13.7
uv sync --locked --extra dev --extra browser
uv run --locked --no-sync uvicorn app.demo:app --host 127.0.0.1 --port 8012
```

Откройте `http://127.0.0.1:8012`. Временная база удаляется при остановке сервера. Демо не читает путь к рабочей базе и не запускает рабочий React-интерфейс.

## Локальный рабочий запуск

Рабочий режим рассчитан на доверенное окружение. Он может использовать реальные данные, браузерную сессию и внешние сервисы; изучите конфигурацию и флаги перед запуском интеграций.

1. Установите зависимости Python, как показано выше, и Node.js 22.
2. Создайте локальные конфигурацию и профиль из шаблонов: `cp .env.example .env` и `cp data/profile.template.json data/profile.local.json`. Укажите путь к профилю и другие необходимые параметры в `.env`.
3. Запустите backend и интерфейс в отдельных терминалах:

```bash
uv run --locked --no-sync uvicorn app.api:app --host 127.0.0.1 --port 8000
```

```bash
cd dashboard
npm ci
npm run dev
```

Интерфейс доступен на `http://127.0.0.1:5173`; запросы к API при разработке проксируются на backend. Первоначальная установка загружает зависимости из пакетных реестров. Для браузерных сценариев также потребуется `uv run --locked --no-sync playwright install chromium`.

Не размещайте рабочий API в открытом доступе без аутентификации и сетевой защиты. Реальные отправки управляются отдельными настройками и командами; используйте dry-run и проверяйте состояние перед включением отправки.

## Архитектура

```text
HH / API / browser ──> application service ──> scoring ──> SQLite
                            │                                │
                            └── draft generation             └── FastAPI ──> React

Demo: synthetic vacancies ──> scoring ──> temporary SQLite ──> read-only UI
```

`backend/app/domain.py` содержит модели, а `scoring.py` — правила оценки; `repository.py` отвечает за хранение; `agent.py` связывает поиск, проверку дублей и подготовку черновиков. Интеграции и маршруты вынесены отдельно. Подробнее — в [описании архитектуры](docs/architecture.md) и [модели безопасности](docs/SECURITY_MODEL.md).

Оценка возвращает не только число, но и причины совпадений и штрафов. Повторные вакансии отсеиваются по идентификатору, а черновики дополнительно проверяются на дубли по компании и названию. Результаты хранятся локально и доступны для повторного просмотра.

## Проверки

```bash
uv run --locked --no-sync ruff check backend tests
uv run --locked --no-sync pytest -q
cd dashboard && npm ci && npm run build
```

CI выполняет эти проверки на Python 3.11 и Node.js 22. Браузерные и внешние действия в тестах изолируются или заменяются заглушками; успешные тесты не подтверждают актуальность сторонних интерфейсов HH.
